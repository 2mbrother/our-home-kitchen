# 우리집 요리

민형과 유민의 요리 모음과 인쇄용 메뉴판입니다. GitHub Pages에서 로그인 없이 볼 수 있습니다.

## 최초 게시 설정

저장소 Settings → Pages → Build and deployment에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/(root)**로 선택하고 Save 합니다.

주소: https://2mbrother.github.io/our-home-kitchen/

## 편집 잠금

사이트 방문, 검색, 상세보기, 메뉴판 보기와 인쇄는 누구나 사용할 수 있습니다. 새 메뉴 추가, 메뉴 수정·삭제, 메뉴 관리와 엑셀 가져오기는 편집 비밀번호를 입력해야 사용할 수 있습니다. 비밀번호는 페이지를 새로고침하면 다시 필요하며, 메뉴 관리의 ‘편집 잠그기’로 바로 잠글 수도 있습니다.

GitHub Pages의 정적 화면 잠금이며 서버 인증을 대신하지 않습니다. 실제 공개 메뉴 변경은 GitHub 저장소 권한으로 보호됩니다. 비밀번호를 README에 기록하지 않습니다.

## 메뉴 추가와 공개 반영

1. 사이트에서 ‘새 메뉴 추가’ 또는 ‘메뉴 관리 → 엑셀 / CSV / 백업 가져오기’를 사용합니다.
2. 편집 내용과 업로드한 사진은 브라우저의 IndexedDB에 저장됩니다. 이 단계에서는 다른 방문자에게 공개되지 않습니다.
3. ‘메뉴 관리 → 공개 반영 파일 / 백업 다운로드’를 눌러 `recipes.json`을 내려받습니다.
4. [메뉴 업로드 화면](https://github.com/2mbrother/our-home-kitchen/upload/main)에 파일을 올리고 Commit changes를 누릅니다. GitHub에서 메뉴를 게시하는 작업은 저장소 권한이 있는 계정으로 로그인해야 합니다.
5. GitHub Pages 게시가 끝나면 방문자에게 새 메뉴가 보입니다. 편집한 브라우저는 ‘내 편집본 지우고 공개 메뉴 불러오기’로 공개 버전을 다시 확인할 수 있습니다. 편집본은 반드시 먼저 백업하세요.

엑셀은 첫 번째 시트의 기존 열을 사용합니다: `idx`, `분류`, `요리`, `메인`, `민형_등수`, `유민_등수`, `요리시간`. 같은 번호는 수정하고 새 번호는 추가합니다. 사진과 메모는 유지합니다. 분류는 `메인` 또는 `반찬`이며, ‘메인’ 열은 담당 요리사입니다.

메뉴판의 + 버튼으로 요리를 담은 후 메뉴판 화면의 ‘인쇄 / PDF 저장’을 사용합니다. 전체 메뉴판 PDF 파일은 최초 32개 요리의 고정본입니다.

## 유튜브 조리 영상 링크

요리 상세보기 → 메뉴 수정(또는 새 메뉴 추가)에서 **유튜브 링크**를 붙여 넣어 저장하세요. 상세보기의 **유튜브로 조리 영상 보기**를 누르면 새 창에서 영상을 볼 수 있습니다. 유튜브 일반 영상, youtu.be 공유 링크, Shorts를 지원합니다.

기존 엑셀의 마지막 열에 **유튜브링크**를 추가하고 요리별 영상 주소를 적은 뒤 가져오면 됩니다. `유튜브 링크`, `YouTube URL`이라는 열 이름도 지원합니다. 링크 열이 아예 없는 옛 엑셀은 기존 링크를 유지합니다. 링크 열이 있고 해당 셀이 비어 있으면 기존 링크를 지웁니다. Excel 하이퍼링크 및 `HYPERLINK` 수식의 영상 주소도 가져옵니다. 공개 반영 파일과 백업에도 유튜브 링크가 함께 저장됩니다.

## 개발

Node.js 22 이상에서 `npm install`, `npm run dev`를 사용합니다. `npm run build`는 `docs/`에 빌드 파일을 생성합니다. 실제 게시용 `index.html`은 스크립트와 글꼴을 하나로 묶은 파일입니다. 메뉴 정보와 사진은 저장소 루트의 `recipes.json`을 사용합니다. 웹에서 메뉴를 변경한 뒤에는 이 파일을 `public/recipes.json`에 반영한 후 다시 빌드하세요.

GPT / Sites 호스팅, 서버 API, 외부 데이터베이스 없이 동작합니다. 메뉴 JSON과 처음 제공한 음식 사진, 프리텐다드 글꼴이 저장소에 포함되어 있습니다. 새 사진은 축소한 이미지 데이터로 JSON 백업에 함께 포함됩니다. 토큰과 비밀키는 사용하지 않습니다.
